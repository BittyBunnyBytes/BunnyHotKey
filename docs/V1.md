# AutoHotkey v1 compatibility

BHK runs AutoHotkey v1.1 scripts through a source frontend feeding its native
runtime. Original `.ahk` files do not need to be converted.

```
bhk --console script.ahk
bhk --console --validate script.ahk
bhk --ahk-version=1 script.ahk
bhk --ahk-version=2 script.ahk
```

## Version detection

The default `auto` mode respects `#Requires AutoHotkey v1`/`v2`. Otherwise it
scores the main file: v1-only directives (`#NoEnv`, `#IfWin…`), comma
commands, literal assignment, `ByRef`, `new Class()`, and traditional `If`
forms that v2 can't parse (`<>`, `between`, `in`, `contains`, v1 `is` types)
count for v1; `=>`, `#HotIf`, `catch … as` and function-call commands count
for v2. Forms valid in both versions (`if x = 1`, `if x is Integer`,
`catch TypeError`, `MsgBox obj.Method()`) don't count. Ties go to v2.

If the guessed version doesn't load, BHK tries the other one, so a short
example whose own lines look like v1 still runs when its `#Include`d library
is v2. When neither loads, the error is the one from the guessed version.
An explicit `--ahk-version` that conflicts with `#Requires` fails.

## How it works

`bunnyhotkey/legacy.py` reads the script with v1 line rules (literal command
text, v1 continuation sections, `#CommentFlag`/`#EscapeChar`) and translates
it line by line into BHK's v2 dialect. Commands become calls into the
`__v1_*` runtime library (`bunnyhotkey/lib/v1.py`, `lib/v1gui.py`), v1
expression syntax is rewritten, and the compiler switches to v1 scoping.

All global code - auto-execute section, hotkey bodies and labels - stays in one
label stream, as in v1: a hotkey runs its body as a label, so `Gosub`, `Goto`,
fall-through and label-based timers, menus, `OnExit` and Gui events behave as
they do in v1.

## Supported

- **Hotkeys:** unbraced bodies ending in `return`, stacked hotkeys, inline
  commands, remaps, `#If`, `#IfWinActive`/`NotActive`/`Exist`/`NotExist`, the
  `Hotkey` command with labels, hotstrings.
- **Commands:** all 186 commands of AutoHotkey v1.1 (`tools/ahk_v1_commands.txt`,
  from v1.1's command table): `Send*`, `Mouse*`, `Win*`, `Control*`,
  `String*`, `File*`/`Ini*`/`Reg*`, `Loop` (count, parse, read, files,
  registry), `Gui`/`GuiControl`/`GuiControlGet`, `Menu`, `Progress`,
  `SplashText*`, `InputBox`, `MsgBox` with `IfMsgBox`, `Transform`,
  `SetFormat`, `Sort`, `FormatTime`, `EnvAdd` date math and the rest.
  Arguments follow v1 rules: `%var%` substitution, `% expression`, output and
  input variables, numeric parameters as expressions.
- **Language:** literal assignment (`x = text`), traditional `If` (`=`, `<>`,
  `between`, `in`, `contains`, `is type`), `IfEqual`/`IfInString`/`IfExist`/
  `IfWin…`, `ErrorLevel`, `Gosub`/`Goto`/labels, dynamic variables
  (`dyn%i%`), pseudo-arrays from `StringSplit` and `RegExMatch`, `ByRef`,
  default parameters with `=`, v1 function scoping (globals only when declared,
  super-globals, assume-global), `#NoEnv` and the environment fallback,
  v1 math (blank for non-numbers and division by zero, blank variables count
  as 0 in `++`/`+=`, 32-bit `~`, literal number text kept on assignment),
  `#EscapeChar`/`#CommentFlag`, unrecognized `#name` lines as ordinary code,
  `catch` taking any thrown value, `try` without `catch`.
- **Objects:** v1 objects and arrays (`Insert`, `Remove`, `MaxIndex`,
  `HasKey`, case-insensitive keys, `Obj*` functions, `_NewEnum`), `new`,
  classes with `base.Method()`, `obj.base` as the class, static members seen
  from instances, `__New` returning a replacement object, prototype objects via
  `base:`, reassignable class variables, `Exception()`, `Func()`/`%fn%()`.
- **Built-in functions with v1 behaviour:** `InStr`/`SubStr` (0 = from the
  end), `RegExMatch` modes, `StrReplace`, `VarSetCapacity`, `NumGet`/`NumPut`
  on variables, `DllCall` type names, math functions returning `""` on bad
  input, `LV_*`/`TV_*`/`SB_*`, `ComObj*`.
- **Gui:** numbered and named Guis, `g`-labels (labels or functions) and
  `v`-variables, `GuiControl, Choose, ctl, |N` firing the g-label, `Submit`,
  `+Delimiter`, multi-select ListBox, `Check3`, list `Sort`,
  `+LastFound` and other options, `GuiClose`/`GuiEscape`/`GuiSize`/
  `GuiContextMenu`/`GuiDropFiles` labels, ListView/TreeView/StatusBar
  functions, all on BHK's GTK Gui.

## Not reproduced

- Behaviours of releases before v1.1, and v1's 32-bit/ANSI builds
  (`A_IsUnicode` is 1).
- Anything that's Windows-only in v2 too: see the "missing" list in
  [PARITY.md](PARITY.md).

## Tests

- `tests/conformance/v1_language.ahk`, `v1_gui.ahk` and `v1_hotkeys.ahk` - conformance
  checklists, one v1 feature per section with its expected output taken from
  the v1.1 documentation and source semantics (not from BHK). Run them with
  `python3 tools/conformance.py v1_language v1_gui v1_hotkeys [-v]`; the parity
  chart's v1 rows are their pass rates. The Gui suite needs a display and the
  hotkey suite drives the real X11 desktop.
- `tests/scripts/v1_lang.ahk` - language, commands, objects and classes,
  checked against `v1_lang.expected`.
- `tests/scripts/v1_gui.ahk` - the v1 Gui commands and control functions.
- `tests/test_v1.py` - six real hotkey scripts (game macros): startup, toggle
  state, loops, mouse output variables and window conditions on the null
  backend. It doesn't establish in-game behaviour.

`python3 tests/run.py` runs all of them with the v2 regression tests.

Syntax reference: [official v1 language documentation](https://github.com/AutoHotkey/AutoHotkeyDocs/blob/v1/docs/Language.htm).
